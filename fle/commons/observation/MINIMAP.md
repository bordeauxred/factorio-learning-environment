# Minimap observation

An independent, north-up **float32 `(14,128,128)`** tensor, at **four world tiles
per cell**, covers **512×512 tiles**. There are no buildability channels.
The origin follows the tracked character and snaps down to a multiple of four
tiles, putting the character in cell `[64,64]`. A fixed center can be supplied
to the Lua configuration for diagnostics. Configure once per episode.

## Channels

All indices are zero-based. Arrays are indexed `[channel,y,x]`.

| Index | Name | Cell value |
|---|---|---|
| 0 | `explored` | Available-terrain fraction; currently 0 or 1 because exploration is chunk-granular |
| 1 | `water` | Water tiles / 16 |
| 2–6 | `iron_ore`, `copper_ore`, `coal`, `stone`, `uranium_ore` | Sum of resource amounts whose centers fall in the cell |
| 7 | `crude_oil` | Sum of engine resource amounts; not displayed yield percentage |
| 8 | `trees` | Count of tree centers |
| 9 | `rocks_cliffs` | Fraction of tiles intersecting rock/cliff bounding boxes |
| 10 | `friendly_structures` | Fraction of tiles intersecting own/allied static structure bounding boxes |
| 11 | `enemy_structures` | Fraction of tiles intersecting enemy-force spawner/turret bounding boxes |
| 12 | `enemy_units` | Count of enemy-force mobile unit centers |
| 13 | `player` | One at the tracked character's cell, zero elsewhere |

Occupancy unions tile bits, so overlapping bounding boxes never exceed one.
This is a coarse bounding-box occupancy signal, not a placement legality mask.
Friendly structures exclude characters, mobile units, vehicles, robots, ghosts
and transient effects. Resource amounts and counts are unnormalised; model-side
normalisation is separate. Resource sums have float32 precision on the client.

The default `visibility="generated"` matches the existing FLE terrain stream:
terrain generated by the scenario is available to the agent. Thus `explored`
means available terrain, not player exploration in the graphical game.
`visibility="charted"` instead requires the force's `is_chunk_charted` result;
generated but uncharted chunks expose zero in all first 13 channels. In the
isolated headless test scenario, chart requests remained pending despite
advancing game ticks, so the generated mode is used for the performance report.
The selected mode is included in every observation's metadata. Sampling never
requests chunk generation or charts new territory itself.

Before a chunk has been sampled, or after invalidation, its first 13 channels
are **−1**, and `sampled_ticks` is **−1**. This differs from sampled unavailable
terrain (`explored=0`, other channels zero). The player channel is refreshed
every drain and does not depend on terrain availability.

## Minimap alone

Use this checkout's `open_world` scenario. With a connected RCON client `rc`:

```python
from fle.commons.observation.minimap import MinimapCache

minimap = MinimapCache()
minimap.configure(rc, chunk_budget=4)  # default generated-terrain visibility

# Each observation:
minimap.apply(rc.send_command("/sc obs_minimap_drain()") or "")
obs = minimap.observation()
tensor = obs["values"]            # float32 (14,128,128), zero-copy
sample_ticks = obs["sampled_ticks"]  # int64 (128,128), first 13 channels
origin = obs["origin"]            # world tile at array [0,0]
# Also: tick, surface, force, generation, stride, channels, visibility.
```

The world rectangle for array cell `(x,y)` is
`[origin_x+4*x, origin_x+4*(x+1)) × [origin_y+4*y, origin_y+4*(y+1))`.
Copy arrays when retaining observations across later polls. An owned float32
map plus copied timestamps takes **1 MiB**. The live client additionally retains
full overlapping chunks for scrolling (about 0.81–0.92 MiB of array data, plus
Python objects), so this is not the entire cache memory footprint.

## Combined with the narrow observation

Run with `PYTHONPATH=.:tests/benchmarks` for the existing reference TensorClient:

```python
from benchmark_tensor_obs import TensorClient

client = TensorClient()
client.apply_entity(rc.send_command("/sc obs_diff_full_sync()") or "")
client.apply_terrain(rc.send_command("/sc obs_terrain_full_sync()") or "")
client.buildability.configure(rc)  # narrow 63×128×128 buildability view
client.minimap.configure(rc)

# Each observation: one RCON round trip.
response = rc.send_command("/sc obs_all_drain()") or ""
entities, _, terrain = response.partition("~")
client.apply_entity(entities)
client.apply_terrain(terrain)
grid, globals_, entities, entity_mask, build, minimap = client.observation(
    include_buildability=True, include_minimap=True
)
```

The original four-tuple remains the default. Either optional view can be
requested independently; when both are requested, buildability precedes minimap.
The existing context grid remains `(17,96,96)` over 288×288 tiles, while
buildability covers 128×128 tiles and the minimap covers 512×512 tiles.
Keep each view's coordinates; their equal/different tensor dimensions do not
imply equal world extents. The context origin is
`(client.center_x-144, client.center_y-144)`.

## Sampling, invalidation and recovery

The server samples up to `chunk_budget` **32×32-tile chunks** per drain
(default 4, range 1–64), aggregating all 13 world channels together. It starts
near the center and cycles through the viewport. A stationary window overlaps
256–289 chunks, depending on alignment: without invalidation traffic, initial
coverage needs 64–73 polls at the default budget.

Build/mine/die/rotate/clone, tile, chunk-generation and chart events invalidate
affected chunks. `obs_diff_touch(entity)` also invalidates its current area.
Dirty jobs alternate with the normal traversal, so sustained invalidations
cannot starve the far field. Chunk sampling queries current engine state;
rolling traversal detects eventless mutations, resource depletion and enemy
movement, including old positions. A chunk-count budget bounds the number of
queries, not their wall-clock cost or the number of entities found.

Unchanged samples transmit a timestamp record instead of the full sparse
payload. Timestamps expose staleness: enemy locations and other channels are
not guaranteed current between samples. There is no fixed tick-age bound;
refresh depends on polling rate, budget, movement and invalidation traffic.
Even in charted mode, sampled data comes from current world state in explored
chunks, not Factorio's historical fog-of-war rendering.

- `obs_minimap_full_sync()` starts a new generation and progressively sends
  full chunk records; apply the response, then continue draining.
- `obs_minimap_invalidate()` clears server cache state after bulk eventless edits.
- `obs_minimap_configure{enabled=false}` clears the view on the next drain.
- Surface/force changes reset the generation; scrolling retains overlapping
  chunks on both server and client. Reconfigure after restoring another world.

The minimap is one ordered, single-consumer stream. Use either its standalone
drain or the combined drain for a given cache; do not split them between
consumers. Standalone draining does not consume the original entity/terrain
buffers, which can still overflow if never consumed; those buffers remain
independent of the minimap.

## Protocol and validation

The combined stream retains `entities~terrain` framing. The minimap adds these
semicolon-separated records to the terrain half:

- `M1,generation,surface,force,x0,y0,tick,player_x,player_y,present,visibility`
- `Moff,generation`
- `Cgeneration,cx,cy,tick,index:value,...` replaces all 13×8×8 chunk cells;
  omitted values are zero, flattened channel-first with row-major cells.
- `Sgeneration,cx,cy,tick` refreshes the timestamp of unchanged cached data.
- `Vgeneration,cx,cy` marks a chunk unknown pending resampling.

Generation checks reject old streams. Coordinates are world chunk coordinates;
client clipping handles partially visible chunks at viewport edges.

```sh
PYTHONPATH=. python -m pytest tests/observation_diff/ -o addopts='' -q

```

Tests use real Factorio for all 14 channel semantics, availability filtering,
budget bounds, entity invalidation, silent enemy movement, player scrolling,
surface reset, full-sync generation and combined compatibility. Decoder tests
also cover unchanged-chunk restoration after invalidation and stale generations.
The benchmark reports initial fill, standalone minimap, narrow-only baseline,
and combined polling, separating RCON, decoding, assembly and owned CPU/NumPy
training samples. It excludes GPU transfers and model execution.

The [profiling report](../../../tests/benchmarks/results/minimap-2026-09-18.md)
records 4.60 ms median / 6.64 ms p95 for minimap-only polling through an owned
sample, and 7.03 ms / 9.27 ms combined with the narrow observation. The same-run
narrow-only baseline is 4.34 ms / 6.33 ms. Initial minimap fill took 64 polls
(about 0.35 seconds) at the benchmark's fixed, chunk-aligned center.
