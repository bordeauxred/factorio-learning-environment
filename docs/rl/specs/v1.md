# Spec v1: environment fixes and a deeper off-policy learner

Status: to implement. Two parallel Codex sessions: D1 (environment and
schema), D2 (learner). Read `docs/rl/results/first_curves.md` first: it has
the v0 measurements every item below answers.

Rules unchanged: never modify `fle/env/` or `fle/cluster/`; reward stays the
raw change in `score()[1]`; intrinsic or exploration machinery may touch the
behaviour policy only, never replay rewards or targets; support masks only.

## D1. Environment: `fle/rl/schema.py`, `fle/rl/env.py`, `fle/rl/observation.py`, `fle/rl/fake_env.py`

1. **Enemies.** FLE's `FactorioInstance(peaceful=True)` is not honoured by the
   open_world scenario: `surface.peaceful_mode` is false and worm turrets
   killed the character in 15% of v0 episodes. In `FleMacroEnv.reset()`, after
   `instance.reset`, run one RCON block that sets
   `game.surfaces[1].peaceful_mode = true` and destroys every entity with
   `force = "enemy"` on the surface (`raise_destroy = false`), then drains.
   Keep the death terminal exactly as it is and log a `deaths` counter; the
   acceptance run must report zero deaths. Record in the env docstring that
   this restores FLE's intended peaceful default.
2. **PLACE gets its own head.** Add head `placeable` after `item` in
   `schema.HEADS`, sized to the number of vocab items whose `place_result`
   resolves to a `Prototype` (compute at import; expose `PLACEABLE_NAMES`,
   `PLACEABLE_INDEX`). `OP_HEADS["PLACE"] = ("placeable", "offset",
   "direction")`. Its mask: item held with count > 0. The `item` head is now
   read only by INSERT and EXTRACT; its mask stays the union of held items and
   items in entity slots. Bump `SCHEMA_VERSION` to `macro-v1`. Every layout
   constant must still derive from `HEADS`; nothing hand-written.
3. **CRAFT mask checks ingredients recursively.** Exactly the check
   `craft_item/server.lua` performs: a recipe is admitted iff it is enabled,
   its category is hand-craftable, and its ingredients can be met from the
   player inventory, recursing into enabled hand-craftable sub-recipes, with
   shared ingredient accounting across the recursion for one unit of output.
   Implement as a pure function over (inventory, enabled set, vocab) in
   `fle/rl/ops.py` with offline tests: wooden chest from 2 wood admitted;
   burner mining drill admitted with 9 iron plates and 5 stone (gears
   recursive) and refused with 8 plates; stone furnace refused with 4 stone.
4. **Horizon.** Default `max_steps=256`, `max_ticks=216_000`. Keep the CLI flags.
5. **Fake env and tests.** Update `FakeMacroEnv` and every offline test to the
   new schema. Do not edit `fle/rl/dqn.py` or `fle/rl/puffer/` beyond what a
   schema constant rename forces; D2 owns the learner. If a learner file must
   change, keep the diff minimal and list it.

Acceptance: pytest for `tests/rl/` offline suites; ruff; live
`python -m fle.rl.env --port 27000 --episodes 3 --steps 128 --seed 1` reporting
zero deaths, PLACE ok rate above 60% of PLACE attempts, CRAFT ok rate above
80% of CRAFT attempts, and HARVEST still succeeding. Print the output
verbatim. Use ports 27000 and 27001 only.

## D2. Learner: `fle/rl/dqn.py` (owner) and `fle/rl/eval_policy.py`

v0 DQN reached median APS 389 over its last 39 episodes with a plain
branching double DQN; it plateaued on a stone-brick economy and never
crafted past furnaces and chests. The next rungs need iron plates extracted
from a furnace, gears, a burner drill placed on ore and fuelled: a long
conjunction that epsilon-greedy will not find. Add, behind flags, keeping the
v0 path as `--algo dqn`:

1. **Prioritized replay** (`--per`, alpha 0.6, beta 0.4 -> 1.0), proportional,
   with importance weights in the loss. This changes sampling only.
2. **Bootstrapped DQN** (`--algo bootdqn --heads K`, default K=8): K value
   heads on the shared encoder, each a full branching dueling head; Bernoulli
   masks with p=0.5 stored per transition; one head sampled uniformly per
   episode and followed greedily for that episode (no epsilon, or a small
   floor `--eps-floor 0.02`); the target for head k uses the online argmax of
   head k (double DQN per head). Randomized prior functions
   (`--prior-scale 1.0`, Osband 2018): each head's Q is `Q_k + scale *
   P_k(s,a)` with `P_k` a frozen random network of the same shape. Log which
   head acted and per-head mean max-Q.
3. **Multi-server workers.** `--ports 27000,27001,27002` runs one env per
   port on threads sharing one replay and one learner; count env steps across
   envs; keep the per-100-step logging and env JSONL logs per port.
4. **Resume and eval.** `--resume <checkpoint>` restores nets, optimizer and
   step counter. `fle/rl/eval_policy.py --checkpoint ... --port ... --episodes
   N` runs the greedy policy (head-averaged Q for bootdqn) with the env
   logging on, so the plotting script can compare greedy against the
   behaviour policy.
5. Schema is being bumped to `macro-v1` concurrently by D1 (a new `placeable`
   head, 256-step horizon). Read all head names and sizes from
   `fle.rl.schema` at runtime; do not hard-code v0 numbers. Develop against
   `FakeMacroEnv`; if it changes under you mid-way, re-run your tests.

Acceptance: on `FakeMacroEnv`, `--algo bootdqn --per --heads 4` for 20k
steps beats the random baseline and is not worse than `--algo dqn` at the
same budget (report both); a maximally masked batch gives finite loss for
every head; ruff and pytest clean; no live server use.
