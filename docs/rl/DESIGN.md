# Goal-conditioned off-policy RL for Factorio Learning Environment

## 1. Executive summary

Train one goal-conditioned agent on the open track. At reset, sample an automatic-production goal. The agent acts in an empty-inventory, research-locked open-world game. Store every transition, including failures. Hindsight Experience Replay (HER) relabels a trajectory that misses its assigned goal with a production goal it actually reached. Evaluate on held-out goals and by setting the goal to an existing named FLE throughput target. The existing open-play task has no quota success condition; open_play_production is an Inspect evaluation configuration, not a constructible Gym task (fle/eval/tasks/task_definitions/unbounded/unbounded_tasks.py:66-75,86-114,124-135; fle/eval/tasks/task_definitions/task_registry.py:43-66; docs/rl/research/05-open-track-goals.md:1-17).

The observation restores the original two-resolution map and 512-entity scale. It is a versioned flat float32 Box for batching. Fixed blocks sum to 36,368 floats. G is the number of goal-capable item names in the pinned live export; M is the sum of the action-mask lengths. Exact length is 36,368 + 2G + M, likely about 38,000 to 40,000 after the live vocabulary is known. This is the original roughly 37k-float scale, not the previous 14,177-float reduction. Full live G, action cardinalities, and final byte count are **UNVERIFIED** until export (docs/rl/research/01-action-space.md:40-50; docs/rl/research/02-observation-space.md:1-3).

|---|---|---|

| RESEARCH | technology | Unlock a production path |

The learner is an owned, vendored CleanRL-style single-file branching double DQN with dueling heads, three-step returns, prioritized replay, eight learner updates per new transition, and periodic Q-head resets. The shared encoder takes the goal vector as a UVFA input. Replay contains exact achieved counts and true ticks, so reward for a new goal is recomputed from stored bytes. Use four future HER relabels per real transition where positive future progress exists. A non-parametric Goal-GAN-style curriculum samples and perturbs achieved goals, focusing on goals with estimated real-episode success between 0.1 and 0.9. A literal LSGAN is a later comparator behind the same generator interface (docs/rl/research/07-rl-stack.md:23-55,100-151).

Choose a pure sparse, goal-conditioned first-hit reward. A true-game-tick discount favors faster achievement. Do not put the old readiness or rate potential into the HER reward. The earlier design correctly identified a long zero-output bootstrap chain, but a readiness potential would require goal-specific, exact, offline-stored machine facts. The current status/inventory cache cannot guarantee those facts. Seed replay with scripted empty-start traces and initially reachable goals; keep readiness as an observation and diagnostic. HER cannot create success from all-zero traces (fle/cluster/scenarios/open_world/observation_diff.lua:80-170,290-352; docs/rl/research/05-open-track-goals.md:49-60).

Use one Factorio server per asynchronous worker. Reuse a server across episodes, but reset player position, counters, caches, and episode epoch. Training episodes end at 256 policy actions or 3,600 actual game seconds; reaching a goal does not end them, which preserves later HER futures. The 5,000 steps advertised by open play are a runner budget, not Gym truncation (fle/eval/tasks/task_definitions/unbounded/unbounded_tasks.py:66-75; fle/env/gym_env/environment.py:453-465,519-523). Four servers are a functional probe. At an illustrative 0.5 to 2 seconds per transition, 0.5M to 1M fresh steps need 1 to 8 ideal servers for 72 hours, before learner time and contention. The roughly order-of-magnitude sample-efficiency gain against the previous 10M-step PPO target is **UNVERIFIED** for Factorio (docs/rl/research/07-rl-stack.md:75-99; fle/cluster/run_envs.py:233-253).

This replaces the previous stocked iron-ore PPO milestone. PPO cannot use HER replay; the open track needs crafting, recipes, connections, and research; and the smaller tensor and three-prototype mask hid essential factory state. PufferLib is out because its Python trainer is PPO-only, its pins conflict with FLE, and it adds no speed to a server-bound environment (docs/rl/research/07-rl-stack.md:7-22; docs/rl/research/04-pufferlib.md:183-217).

## 2. Detailed design

### 2.1 Vocabulary and observation

Export live Factorio 2.0.73 base-game prototypes.item, prototypes.entity, prototypes.recipe, prototypes.technology, defines.entity_status, and installed mod name/version pairs. Include fluid names as a separate catalog for later goal support. Commit canonical JSON to data/rl/vocab/factorio-2.0.73-base-v1.json. Sort catalogs bytewise by name. Include schema_version, Factorio version, scenario, sorted mods, items (name, fuel value, place result), entities (type, footprint, collision box, max health, crafting categories and speed), recipes (category, energy, typed ingredients/products, amounts and probabilities), technologies (prerequisites and recipe-unlock effects), and status name/integer pairs. Unavailable fields are explicit null. content_sha256 hashes compact, sorted-key UTF-8 JSON with fixed numeric formatting, excluding the hash field. Page the export by category/name if a reply is too large. Every server re-exports once before reset and refuses a hash mismatch; normal startup never rewrites the artifact. Dynamic researched/enabled bits are not part of the static hash. Full live counts, category fields, exact placeability and center parity remain **UNVERIFIED** until validation (fle/env/game_types.py:83-113,304-305,308-332; data/recipes/recipes.lua:1-18; fle/env/mods/serialize.lua:594-610; fle/env/tools/agent/place_entity/server.lua:136-149). For example, a mod adding an inserter cannot silently change a saved checkpoint's IDs: the hash fails before a policy acts.

Use PAD=0 and OTHER=1 for embedded entity/item/recipe IDs. Action heads address complete pinned catalogs by stable ID; a mask decides which entries the V0-open tools support or the player can use. Schema version, hash, and head dimensions travel with checkpoints and replay. G is the sorted subset of exported item names whose production counters and manual subtraction pass calibration. This is the complete calibrated item-goal vocabulary, not the four-item curriculum seed. Do not clip G, aliases, or action catalogs to 128 or 256. The fixed tech_mask(256) is a capacity declaration for the pinned base artifact, not permission to discard names: if the live technology count exceeds 256, bump the versioned tensor width before training. Inventory and flow tables may omit **policy feature rows** under overflow; the complete client counter cache and all exact achieved lanes remain intact. Record overflow in globals. The 212-row offline recipe snapshot lacks products, categories, unlocks and energy, and the Python Prototype enum contains aliases and nonentities, so neither defines a complete action vocabulary (data/recipes/recipes.lua:1-18; fle/env/game_types.py:83-113,304-305; docs/rl/research/01-action-space.md:40-50).

Every achieved_i and goal_i is an unscaled, unclipped, nonnegative integer-valued float32. globals[0] is unscaled episode-relative game.tick, also integer-valued float32. Float32 represents every integer from 0 through 2^24 = 16,777,216 exactly; it does not represent every larger integer. The 3,600-second episode cap is 216,000 nominal ticks, inside that range. If any exact count or tick exceeds the range, reject that trajectory before replay insertion, record precision_limit, and move to a versioned split-integer or int64 sidecar schema before longer runs. Never round an over-range count or compare a logged feature to a HER threshold. The log-scaled flows and entity counts are policy features only. For example, log1p(40) with clipping cannot reliably answer whether a relabelled goal of 39, 40 or 41 plates was crossed; exact achieved values can (docs/rl/research/05-open-track-goals.md:34-48).

The fine grid is centered on floor(player.x),floor(player.y). Cell (i,j) reads world tile (floor(px)-16+i, floor(py)-16+j) and has channels, in order: known, iron ore, copper ore, coal, stone, uranium ore, water, obstacle, mining, crafting/smelting, transport/inserter, storage/power/other functional structure. Preserve named ore wire records. A present ore uses 0.1 + 0.9 min(1,log1p(100 bucket)/log1p(10000)); absence is zero. The persistent map retains other names and reports them as unmapped, never folds them into iron. The coarse grid covers 128x128 tiles with 4x4 cells. Channels are known-tile fraction, eligible entity density min(count/16,1), working fraction, no-power fraction, input/fuel-starved fraction, and output-blocked fraction. Count each eligible machine/logistics entity once by center cell; disabled and other statuses remain in the denominator. An unknown tile has known=0 and zero content, not an assertion of empty land. A one-tile gap between drill and furnace is visible at fine resolution; a blocked furnace 70 tiles away can appear in the coarse fault field. Six coarse channels cannot identify a distant ore type, so typed ore remains in the persistent map and task focus can direct movement; expand the coarse schema if held-out exploration fails from missing remote ore identity. Existing terrain records contain names, but the benchmark merges them and uses 3-tile cells (fle/cluster/scenarios/open_world/observation_diff.lua:187-223; tests/benchmarks/benchmark_tiered_obs.py:57-70; tests/benchmarks/benchmark_tensor_obs.py:44-58,361-380; docs/rl/research/06-simulator-improvements.md:53-70).

Do not infer status integers from EntityStatus.from_int, which indexes enum declaration order. Generate a code-to-group map from live defines.entity_status. Groups are other, working, no_power, no_fuel, starved, output_blocked, disabled. Map no_power, low_power, not_plugged_in_electric_network and recharging_after_power_outage to no_power; no_fuel, no_food and low_temperature to no_fuel; input/fluid/science shortage and waiting_for_source_items to starved; full_output, full_burnt_result_output, not_enough_space_in_output and waiting_for_space_in_destination to blocked; named disabled/frozen/broken statuses to disabled. Keep neutral normal, empty, no_recipe, and unrecognized codes in other. Fuel and input starvation are distinct entity groups but combine in the coarse starved fraction. A live name absent from the export is **UNVERIFIED**, not a reason to guess its numeric code (fle/env/entities.py:46-150,155-167; docs/rl/research/06-simulator-improvements.md:47-55). Raw status 7 cannot be called working because it is seventh in a Python enum; the exported pair determines its label.

Keep an unbounded client dictionary keyed by unit_number; select 511 real rows plus row 0, the synthetic player anchor. Deterministic quotas are 191 nearest to player/task focus, 128 task-relevant type/recipe/area candidates, 96 fault-status candidates, 48 spatially dispersed candidates, and 48 recently changed candidates. Skip duplicates and fill short strata by relevance, freshness, then distance, with unit number as final tie-break. Preserve row-to-unit mapping until the action completes. Report selected_relevant_fraction, live relevant count and stale selected count. A 700-belt cluster must not hide one distant blocked furnace: the fault quota selects it while the recall diagnostic reveals remaining omissions (tests/benchmarks/benchmark_tensor_obs.py:437-468; docs/rl/research/06-simulator-improvements.md:78-87).

The 32 entity lanes are fixed in encoder schema v2. Lanes 0-3 are stable entity ID, recipe ID, validated status group and functional class ID. Lanes 4-11 are player-relative x/y divided by 64, direction sine/cosine, footprint width/height divided by 8, health fraction and crafting-progress fraction. Lanes 12-19 are log-scaled joules, fuel count, surveyed entity-item count, fluid amount, then pickup dx/dy and drop dx/dy divided by 8. Lanes 20-23 are joined log-scaled **physical** electric supply watts, demand watts, satisfaction and network-valid bit. The arbitrary network ID remains a join key in the client cache and is never a policy magnitude. Lanes 24-31 are value age, check age, fresh bit, task-relevant bit, problem-status bit, recently changed bit, task-resource overlap bit and inventory-coverage bit. Normalize and clip numeric policy features using fixed schema scales; embed integer ID lanes. Unavailable measurements have value zero and validity zero. Two poles with network IDs 1 and 9000 but identical 200 kW supply and demand produce the same physical features; an uncalibrated meter yields valid=0 (fle/cluster/scenarios/open_world/observation_diff.lua:80-170; fle/env/mods/serialize.lua:813-823; docs/rl/research/06-simulator-improvements.md:88-103).

Inventory holds up to 128 nonzero player-main-inventory kinds, sorted by stable item ID, with [item_id,log1p(count)]. Flows holds up to 128 item kinds ordered by goal relevance, activity, then ID. Its actual per-minute rates use a tick-stamped 3,600-tick window and become log1p(rate)/log1p(60) clipped to one for the policy. Stored is log1p(surveyed_count)/log1p(1000), not an exact force-wide stock claim. Surveyed stock includes player main inventory and tracked force-owned machine/container input, output and fuel inventories whose slot semantics were validated; it excludes belts, transit and unsurveyed carriers. Carry coverage and sample age, and mark invalid when incomplete. Hand-mined ore moved player-to-chest should conserve surveyed stock once both records reconcile, while a belt item is outside this metric (fle/env/tools/agent/inspect_inventory/server.lua:9-17,56-78; docs/rl/research/06-simulator-improvements.md:35-44). Flow rates are sampled features; exact achieved updates at **every** action boundary from cumulative produced counters and manual ledgers in the same drain. A 600-tick rate sample alone would make HER's state stale. Counter direction and manual-ledger completeness remain **UNVERIFIED** until live drill/hand-work calibration (fle/env/tools/admin/get_production_stats/server.lua:10-39; fle/env/tools/agent/score/server.lua:1-11; fle/env/utils/achievements.py:18-40).

Tech_mask is the complete initial researched bitset from full sync, updated on completion, reversal, reset and periodic audit. The research-action mask separately checks enabled, unresearched and prerequisites. The 16 globals are: exact episode tick; actions remaining divided by 256; spawn-relative x/y divided by 128; log entity count; fine known fraction; coarse known fraction; research progress; log total electric supply; log demand; satisfaction; power-valid bit; flow sample age; surveyed-stock coverage; maximum selected check age; and overflow/invalid-state bit. All except tick are bounded policy features. Report selected_relevant_fraction in diagnostics. Goals replace bounded-task text/quota lanes. Focus is host metadata for masks, while the exact tick and remaining-action fraction tell Q how close the finite-horizon limit is. The exact tick always resides in the stored observation; an int64 audit copy does not substitute for it (fle/cluster/scenarios/open_world/observation_diff.lua:356-379; docs/rl/research/05-open-track-goals.md:34-48).

### 2.2 Action geometry, masks and dispatch

Use the ordered MultiDiscrete tuple (op, anchor, prototype, item, recipe, technology, peer, dx, dy, direction, quantity, duration, connection_type). Its dimensions are [12,512,P+1,I+1,R+1,T+1,512,18,18,5,4,4,4], where P, I, R and T are complete pinned placeable-entity, item, recipe and technology catalog sizes. Offset indices 1-17 mean -8..8; 0 is unused. Directions 1-4 are cardinal. Quantity 1-3 means 1, 5, 20; duration 1-3 means target 1, 5, 15 game seconds; connection type 1-3 means belt, pipe, power. WAIT is op 0; the rest follow the executive table, with INSERT=7, EXTRACT=8, SET_RECIPE=9, CONNECT=10, RESEARCH=11. PICKUP, ROTATE, INSERT, EXTRACT and SET_RECIPE require a real entity row. Row 0 is the player anchor for MOVE, HARVEST and PLACE only. CONNECT requires distinct real endpoints, or a validated player-position endpoint for a connector-specific case. connect_entities resolves ports, paths, inventory and placement through multiple operations; one RL action is not one atomic RCON mutation (fle/env/tools/agent/connect_entities/client.py:57-77,109-199,448-486; docs/rl/research/01-action-space.md:5-33).

PLACE(prototype,anchor,dx,dy,direction) resolves the sampled row, adds integer offsets, normalizes to the exported footprint's legal center parity, and calls place_entity(...,exact=True). Reject normalization that moves outside the intended tile and verify the returned center. Offshore pumps currently force inexact placement: add a dedicated exact shoreline candidate/confirmation path before unmasking that prototype. It remains in the catalog. place_entity_next_to is unsuitable because it may search another site (fle/env/tools/agent/place_entity/client.py:19-26; fle/env/tools/agent/place_entity/server.lua:193-204; fle/env/tools/agent/place_entity_next_to/server.lua:179-230,320-378). For example, PLACE(chest,furnace,+1,0,north) must name one candidate center. Silently moving the chest two tiles away would corrupt spatial credit assignment. MOVE and HARVEST use the same anchor-relative geometry but retain their path/retry macro behavior (fle/env/tools/agent/move_to/client.py:29-69; fle/env/tools/agent/harvest_resource/client.py:59-91).

CONNECT stays in the first implementation. A 40-tile belt built through separate PLACE actions consumes at least 40 RL decisions and adds horizon without adding strategy. CONNECT(source,target,belt) asks the existing router to find and lay a path; pipe and power use their validated families. Record placed segments, true ticks, partial mutation and route failure. Mask incompatible endpoints and insufficient connector inventory, but invoke pathfinding only for the sampled tuple; get_connection_amount is itself a compound dry run (fle/env/tools/agent/connect_entities/client.py:80-102,448-486,490-599; fle/env/tools/agent/get_connection_amount/client.py:29-32).

Export full catalogs, but begin V0-open with this **placeable allowlist**: burner/electric drills; stone/steel/electric furnaces; assembling machines 1 and 2; wooden/iron/steel chests; transport/fast belts, underground belts and splitters; burner/standard/long-handed/fast inserters; pipes and pipe-to-ground; small/medium electric poles; boiler, steam engine, lab, pumpjack, chemical plant and oil refinery. That is 28 named base-game entities, subject to live-name and exact-placement validation. Keep every live item, recipe and technology ID. Active masks depend on inventory, character crafting categories, unlocks and machine categories; do not hard-code empty recipe or technology heads. Defer rail, rolling stock, rocket/space and combat placeables until their multi-entity routing, launch or combat semantics have an exact action contract. Offshore pump is a specific exact-placement gate, not a reason to remove the power/fluids chain. A missing live prototype or place result fails validation rather than being silently renamed. The open start has no stocked drills, furnaces, belts or all-research flag, so CRAFT and RESEARCH are necessary for solvability (fle/eval/tasks/default_task.py:15-21; fle/eval/tasks/throughput_task.py:9-31,50-56; docs/rl/research/01-action-space.md:56-75).

Pack binary marginal masks for all 13 heads at the end of the observation in tuple order. Head lengths are the tuple dimensions; compute cumulative half-open slices from the checked-in catalog, never handwritten offsets. WAIT is always valid. Every argument head has index 0 open, even when no nonzero value is usable. anchor=0 is the player only for the three stated ops; otherwise 0 means unused. A required non-anchor head sampled as 0 is a preflight-invalid no-op, consumes one decision and its actual game ticks, and is stored as a real transition. When only WAIT is enabled, all unused heads admit only 0. Otherwise a head's state-only mask is the union of values legal for some enabled op and some partner choice. The decoder ignores irrelevant sampled arguments but retains the original tuple in replay. Assert each head's mask sum is at least one during acting and training. Apply masked_fill(mask==0,-1e8) to float32 Q values, never -inf, and disable float16 autocast on this path. A fully masked head can cause NaN normalization or max behavior; a finite -1e8 and the sentinel avoid the documented ragged-head trap (docs/rl/research/04-pufferlib.md:129-181).

Local masks use player inventory, stable footprints, cached terrain/entities, recursive recipe closure, machine categories, unlocks and researched bits. A direct-ingredients-only CRAFT mask would reject feasible recursive crafting. SET_RECIPE checks machine category and enabled recipe; RESEARCH checks enabled, unresearched and prerequisites; INSERT/EXTRACT use slot rules and surveyed contents. Do not issue can_place_entity for all 17x17xprototype candidates: each is RCON, and its direction probe is unreliable. Do not treat stale cached counts as current (fle/env/tools/agent/craft_item/server.lua:79-109,130-159; fle/env/tools/agent/set_entity_recipe/server.lua:8-44; fle/env/tools/agent/can_place_entity/client.py:33-45; docs/rl/research/01-action-space.md:56-75). For example, furnace-anchor and iron-plate-item marginals can both be legal while their sampled INSERT combination has no suitable slot. Preflight catches the tuple.

Record preflight_invalid, tool_rejected and partial_mutation separately. Always pause and drain after a tool failure: craft, research and place tools can mutate before raising, and Python namespace rollback does not restore the game (fle/env/gym_env/environment.py:450-451,469-474; fle/env/tools/agent/craft_item/server.lua:161-173; fle/env/tools/agent/set_research/server.lua:34-39; fle/env/namespace.py:1158-1164). Measure invalid_combination_rate over non-WAIT choices separately from tool failures. If cross-head rejects exceed 15% over 10,000 non-WAIT transitions across three seeds after mask fixes, add op/argument-conditional legality to branching selection and target selection; preserve the sentinel and preflight contract. Exact path/collision validity remains server-owned. This rate is **UNVERIFIED** (docs/rl/research/04-pufferlib.md:64-88).

### 2.3 Goal, reward, HER and replay

Let C_i(t) be the live cumulative produced item counter and H_i(t) the recorded cumulative manual craft/harvest output. At reset store both baselines. At each paused action boundary, reject any drop in raw or manual counters, then compute a_i(t)=max(0,ΔC_i-ΔH_i) and A_i(t+1)=A_i(t)+a_i(t). Put every A_i into that boundary observation's exact achieved lane. The achieved-goal map is m(s)=A(s). A counter drop invalidates the affected episode and replay records; a new epoch starts after reset. Factorio's score is a priced **net** production/consumption scalar, not a per-item automatic output vector (fle/env/tools/agent/score/server.lua:1-12,309-330,335-408; fle/env/utils/achievements.py:18-40; docs/rl/research/05-open-track-goals.md:18-33). The stats tool's local names conflict with returned names. The scorer treats input_counts as produced, but exact live direction and manual-ledger completeness are **UNVERIFIED** until a hand-mine, hand-craft, drill and furnace calibration (fle/env/tools/admin/get_production_stats/server.lua:10-39; fle/env/tools/agent/score/server.lua:1-11).

A valid goal g has one or more positive integer thresholds and zero elsewhere. Define hit(s,g)=1 iff A_i(s)≥g_i for every positive component. The learning reward is exactly

    r(s,a,s',g) = 1[hit(s,g)=0 and hit(s',g)=1].

There is no dense progress, readiness bonus, invalid-action penalty or per-step rate term in this first HER objective. Do not terminate at a hit. Valid cumulative automatic counts never decrease within an episode, so each goal has one first hitting time. A rate goal can become false when a line stalls and would require exact window history in every stored state. Count goals make relabelling a direct vector comparison (docs/rl/research/05-open-track-goals.md:34-48; docs/rl/research/07-rl-stack.md:132-151). Moving 40 plates from furnace to chest changes stock but not A_iron-plate and cannot create reward. A stalled line retains its count goal, so sustained throughput needs separate evaluation.

Use transition discount β_t=0.99^((tick_next-tick_t)/300), where 300 ticks are five game seconds. Store exact episode-relative true ticks and compute n-step products from them. A 15-second WAIT has β=0.99^3; a one-second action has β=0.99^0.2. Faster first hits are more valuable without wall-time reward. storage.elapsed_ticks is synthetic: movement/crafting and sleep add to it, and sleep waits approximately in wall time rather than advancing exactly that many game.tick ticks (fle/env/instance.py:124-135; fle/env/tools/agent/craft_item/server.lua:161-168; fle/env/tools/agent/sleep/server.lua:1-9; fle/env/tools/agent/sleep/client.py:37-53). Using it would corrupt n-step targets and episode limits. Exact-N-tick stepping is **UNVERIFIED**; use paused true-tick boundaries and record overshoot (docs/rl/research/01-action-space.md:86-91).

The earlier potential used automatic count/rate and small terms for a drill on ore, a fueled drill on ore and a fueled-and-fed furnace. Its reason was sound: before first ore output, a recipe-only count potential is zero. Under explicitly optimistic masks, the prior design estimated random drill placement then fueling at 8.27x10^-5, about one in 12,096 candidate pairs; actual probability is **UNVERIFIED**. Four fueled idle drills were capped at readiness potential 0.20, while one operating drill producing 20 ore could exceed 1.16. Terminal correction Φ(terminal)=0 removed a finite-horizon residual. But a fixed iron-readiness Φ(s) would pay for iron work when HER relabels to copper. A correct Φ(s,g) needs exact, fresh, goal-relevant readiness facts in **both stored observations**, the same β_t as the learner, and terminal correction. The selected, quantized 512-row cache cannot prove full-force readiness counts. Start with sparse HER and scripted bootstrap. If it cannot generate first outputs, add versioned exact readiness lanes and goal-conditioned potential only after an offline recomputation test. Do not quietly reuse the prior goal-independent shaping (fle/cluster/scenarios/open_world/observation_diff.lua:80-170,290-352; docs/rl/research/03-reward-task.md:75-79; docs/rl/research/05-open-track-goals.md:49-60).

Each real replay record is (episode_id, epoch, step_index, obs_t, action_tuple, obs_next, behavior_goal, terminated, truncated, counter_valid, action_outcome, raw_counter_endpoints, tick_t, tick_next, schema_hash). Exact achieved, goal and ticks are also in both observations; side fields audit provenance. The learner derives replay_goal, reward and n-step discount product. A HER copy overlays replay_goal in the goal lane of **both** states. Action, other observation bytes, epoch and real time-limit flag stay the same. Exclude counter-invalid episodes, precision-limit observations, cross-epoch futures and transport failures. A natural 256-action/3,600-second truncation is terminal for this finite-horizon objective. A server fault invalidates the record, rather than becoming a zero-reward terminal. Goal achievement leaves terminated=False. If a tool reports failure after placing a belt, replay stores the observed belt and actual next tick, not a fabricated unchanged state (fle/env/tools/agent/shift_entity/client.py:37-70; docs/rl/research/05-open-track-goals.md:34-48).

Use future HER with k=4. For each original transition, sample four later observations in the **same episode and epoch**. Choose one to three item coordinates that increased after s_t, take their exact counts at the sampled future state as g', and zero the rest. Initially use one coordinate; expand to compound goals as lines appear. If no item increases later, this trajectory yields no positive production HER copy. Keep copies with zero immediate reward because an n-step backup can propagate a later hit. Do not cap achieved at 64 merely because the first curriculum uses small quotas. Tianshou's HER supports future sampling, but its stock Dict-observation and policy assumptions do not supply our whole implementation (docs/rl/research/05-open-track-goals.md:34-48; docs/rl/research/07-rl-stack.md:23-55).

**Worked HER example.** The assigned behavior goal is g={copper-plate:40}. The agent builds an iron line instead. ### 2.4 Curriculum, network and optimizer

The generator interface is sample(policy_version,replay_index,success_table,rng) -> (g,provenance). Begin with single-item {1,4,16} goals for iron ore, copper ore, coal and iron plate, plus a small quota of scripted empty-start demonstrations. These four are a **curriculum seed**, not an observation or action restriction. G contains every calibrated goal-capable item. Add stone, copper plate, gears, cable, circuits and compound thresholds as real trajectories reach them. Estimate GOID success from **assigned behavior goals in full episodes**, never HER labels. Cluster nearby count vectors by active item set and logarithmic quota bin; keep a rolling/Bayesian estimate and uncertainty. Devote 80% of assigned goals to the 0.1-0.9 estimated-success band, 10% to untested/frontier goals and 10% to easy retention goals, so an empty band does not stall training. Sample a real achieved vector, choose one to three nonzero coordinates, perturb exact thresholds with bounded integer increments or small multipliers, and reject unsupported or infeasible goals. Log provenance and real success. After a run reaches 20 iron plates, propose 16, 20 and 24; if 16 succeeds 95% and 24 succeeds 2%, train mostly near 20 while probing 24 (docs/rl/research/07-rl-stack.md:100-130).

This retains Goal-GAN's goals-of-intermediate-difficulty criterion. A literal least-squares GAN generates continuous values while the target is a sparse integer vector: rounding can collapse samples, create meaningless fractional demands or miss the thin frontier between 20 and 21 plates. Replay already contains reachable, correctly typed examples. Implement a literal Goal-GAN/LSGAN second behind the same interface. At equal real environment steps compare unique valid goals, goal success, frontier expansion and real return. This respects the original generator ask as a measurable alternative (docs/rl/research/07-rl-stack.md:100-130).

Use CNN projections for fine and coarse grids, a shared row MLP for all 512 entities, masked mean/max pooling over present rows, and item/recipe/type/status embeddings for integer ID lanes. The entity encoder applies one 32→64→64 row network and yields H in R^(512x64). A shared DeepSets pointer scorer applies an MLP to [h_k;z] for every anchor and peer row, then masks absent/stale rows. It can learn “select this unfueled drill” whether the drill is row 5 or 57; a flat 512-way linear head attaches separate weights to changing slots (tests/benchmarks/benchmark_tensor_obs.py:437-468; docs/rl/research/04-pufferlib.md:45-81). CNN grids, pooled rows, inventory/flow set encoders, tech bits and globals form a 768-feature state vector. Encode exact goal(G,) through a sparse item-ID/count embedding and 256-wide MLP, then **concatenate the 256-goal embedding with the 768-state vector before the shared 1024→1024→512 ReLU Q trunk**. Dueling value and every branch advantage thus depend on g, the UVFA contract. Normalize goal count **inside the network** with a fixed transform; replay retains exact lanes. Use float32 for Q masks and targets. Report input dimensions, parameter count, policy latency, goal-embedding ablations and entity recall before increasing model size.

The primary trainer is owned fle/rl/dqn_her.py in a CleanRL-style single-file form, with small imported encoder, buffer and worker modules. This is roughly 800-1,200 lines of training logic we own and must validate. Tianshou is the batteries-included alternative: its replay/trainer machinery are attractive, but its built-in HER uses a Dict convention and future sampling, and its discrete SAC/standard DQN policies still need our factorized masked Q policy. Switch only if buffer maintenance becomes the dominant engineering cost (docs/rl/research/07-rl-stack.md:23-55). PufferLib is absent from the architecture.

Use branching double DQN with a dueling shared value and per-head centered advantages. Score a complete tuple as the shared value plus operation advantage and the mean of its **active** argument advantages; inactive heads do not affect it. A behavior epsilon policy and online-network bootstrap choose each branch's masked argmax, selecting op first. Target network evaluates that selected complete tuple. Use three-step returns with the true-tick β products; prioritized replay with alpha=0.6 and importance beta annealed 0.4→1, batch 256, target copy every 2,000 learner updates and 20,000-real-transition replay warm-up. Start at eight learner updates per new real transition, cap queued updates when workers outrun GPU, and run replay-ratio 4/8/16 ablations. Reset final Q advantage/value layers and optimizer state every 50,000 **new real transitions** after warm-up; retain encoder and replay, synchronize target, and compare to no-reset control. These are starting hyperparameters, not measured FLE optima. High replay ratio plus periodic resets addresses primacy bias in cited replay-ratio work, but benefit here is **UNVERIFIED** (docs/rl/research/07-rl-stack.md:56-99).

Q-learning's mask is direct: invalid per-head choices get finite large-negative Q values in behavior and bootstrap argmax, so they cannot enter a target. Factorized discrete SAC would also need masks in entropy, temperature loss and soft-value targets; that adds masking surface and tuning for a server-expensive environment (docs/rl/research/07-rl-stack.md:56-75). Branching is an **approximation to the true joint argmax**: anchor, prototype, offset and item values interact, while separate advantages cannot represent every interaction. Valid marginal masks can still yield invalid tuples. Detect failure through the 15% cross-head rejection measure, held-out critic residuals grouped by anchor/prototype and item/target pair, and matched-budget rollouts comparing greedy branches with a small top-3-per-head valid-tuple beam and a scripted baseline. If conditional masks or beam materially improve real success at equal environment steps, add an autoregressive/interaction Q head and keep encoder/replay. Adequacy is **UNVERIFIED** (docs/rl/research/07-rl-stack.md:153-160).

Replay size matters. One 38k-float observation is about 152 KiB; naively storing both states for 200,000 transitions is about 58 GiB before metadata. Store one observation per boundary and reference its successor within an episode. Quantize **policy-only** grids to uint8 and normalized entity/flow features to float16 or fixed point after reconstruction checks; keep IDs and masks as integers/bits and achieved, goal and tick as exact float32 plus audit int64. With 18,432 grid bytes, about 32 KiB for 512x32 half-precision rows and auxiliary fields, a 200,000-boundary ring is roughly 10-14 GiB before Python overhead, not a measured promise. Shard by episode, use packed arrays and measure RSS/decode bandwidth. Never compress an exact reward lane lossily. HER copies store goal overlays/references, not duplicate tensors.

## 6. Throughput and performance test plan

Separate costs: (1) action/tool and internal RCON calls, (2) unpause/pause and true simulation ticks, (3) one v2 drain, client reconcile, tensor and masks, (4) learner updates and replay decode. The move_to + poll benchmark's roughly 30 steps/s omits this RL step (tests/benchmarks/benchmark_action_obs.py:180-189).

The algorithm pivot changes server sizing. Former PPO planning used **10M fresh steps**. Off-policy replay plus HER targets **0.5M-1M fresh steps** as a planning range, a 10-20x reduction in environment samples, with eight gradient updates per fresh step. This Factorio sample-efficiency gain is **UNVERIFIED**; plot it against real-goal success, not HER-labelled success (docs/rl/research/07-rl-stack.md:75-99). Routine training has **no per-episode 30+60-second holdout**; evaluation pays it separately. A 0.5M result is an early diagnostic, not proof of final sample efficiency.
